# Синхронизация подписок с Remnawave

Текущее состояние подписки берётся из панели: срок, ссылка, статус, трафик,
устройства и лимиты. Открытие кабинета, меню бота и фоновая сверка не возвращают
параметры из старой покупки. История покупок хранится отдельно от текущих прав.

- Все слоты подписок сверяются раз в минуту по сохранённому UUID/ID. Изменение
  Telegram ID в панели не перепривязывает слот к другой подписке. Пустой
  дополнительный слот не получает основную подписку автоматически.
- Бот запрашивает актуальную выбранную подписку при открытии меню подключения
  и главного меню. При отключённых дополнительных подписках используется основная.
- Ручные изменения трафика и стратегии сброса не отменяются фоновыми задачами.
  Сброс счётчика использованного трафика не требует восстановления лимита.
- Напоминания о пакетах устройств не меняют лимит. Истечение пакета уменьшает
  лимит только при совпадении с ожидаемым состоянием. Ручная правка передаёт
  управление лимитом устройств панели до следующей покупки тарифа или устройств.
- Новая покупка учитывает фактические лимиты панели. Если администратор заменил
  лимит, прежние пакеты в этой части подписки считаются заменёнными ручной правкой
  и больше не добавляются повторно. Платежи и суммы остаются в истории.
- Незавершённая сверка не перезаписывает покупку, награду или перенос, выполненные
  после начала запроса. Отсутствие пользователя в каталоге панели не удаляет
  аккаунт бота и историю платежей. Удаление подписки подтверждается чтением её
  конкретного UUID/ID при открытии кабинета или меню бота.

Миграция `000058_panel_entitlement_overrides` применяется автоматически при
запуске обновлённого приложения. Обновление сервера:

```bash
cd /opt/Link-Bot && bash ./update.sh
```

Проверки серверной части:

```bash
go test ./cmd/... ./internal/... ./utils/... ./translations/...
```

Интеграционные тесты используют отдельную PostgreSQL-базу, заданную переменной
`PANEL_SYNC_TEST_DATABASE_URL`, и создают временную изолированную схему.
