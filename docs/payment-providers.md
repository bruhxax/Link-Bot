# Подключение новых платёжных сервисов

В **Админка → Интеграции** раскройте карточку сервиса, заполните реквизиты, включите интеграцию и сохраните. Ключи хранятся в зашифрованном виде в базе; добавлять их в `.env` не нужно.

После сохранения в карточке появится **Webhook URL**. Укажите его в кабинете платёжного сервиса, если это требуется в таблице. Входящие уведомления должны быть доступны по HTTPS. Сначала проверьте оплату в тестовом режиме своего сервиса: автотесты Link-Bot проверяют протокол и подписи на имитации API, реальные мерчантские ключи в них не используются.

| Сервис | Поля в Link-Bot | Настройка уведомлений | Официальная документация |
| --- | --- | --- | --- |
| anore.cc | Shop ID, API-ключ, Secret Key | Адрес передаётся при создании платежа как `callbackUrl`; Secret Key нужен для подписи уведомления | [anore.cc](https://anore.cc/docs) |
| MulenPay | Shop ID, API-ключ, секрет подписи из личного кабинета | Вставьте Webhook URL в настройку callback магазина | [MulenPay](https://docs.mulenpay.com/) |
| AuraPay | ID кассы, API-ключ, секретный ключ №2 | Адрес передаётся при создании счёта как `callback_url` | [AuraPay](https://docs.aurapay.tech/) |
| AntiloPay | Идентификатор проекта, Secret ID мерчанта, приватный ключ Base64, публичный ключ Callback Base64 | Вставьте Webhook URL в настройки уведомлений проекта | [AntiloPay API PDF](https://doc.antilopay.com/AntilopayAPI.pdf) |
| ParityPay | ID кассы, секретный ключ №1, секретный ключ №2 | Адрес передаётся при создании счёта как `callback_url` | [ParityPay v2](https://docs.paritypay.net/) |
| Tribute | API-ключ, Shop ID при нескольких магазинах | Вставьте Webhook URL в `callbackUrl` своего магазина | [Tribute Shop API](https://wiki.tribute.tg/for-shops/api/methods) |
| CloudPayments | Public ID и API Secret | Настройте уведомление **Pay**, метод **POST**, формат **CloudPayments**, URL из Link-Bot | [CloudPayments](https://developers.cloudpayments.ru/) |
| Лавешка (Lave Pay) | API-ключ `LAVE-ID-...`, отдельный секрет `whsec_...`, курс ₽/USD | Скопируйте Webhook URL в настройки вебхуков Lave Pay; сохраните и отправьте тестовое событие | [Документация](https://laveshka.io/docs/lave-pay) |
| Smerch | Рабочий API-ключ; секрет вебхука необязателен. Методы выбираются в редакторе тарифов | Скопируйте Webhook URL в кабинет Smerch и подключите `transaction.status_updated` | [Документация](https://docs.smerch.io/) |
| PayHot | Рабочий API-ключ кассы, секрет вебхука, способ оплаты | Вставьте Webhook URL в кабинете PayHot и выберите `payment.succeeded` | [API](https://docs.pay.hot/overview) · [Вебхуки](https://docs.pay.hot/webhooks) |
| Datagio | ID магазина, публичный API-ключ, секрет API, секрет вебхука | Вставьте Webhook URL и тот же секрет вебхука в настройки магазина | [Datagio Finance](https://wiki.datagio.finance/api/payments-create/) · [Вебхуки](https://wiki.datagio.finance/api/webhooks/) |
| Kassa AI | ID магазина, API-ключ, секретное слово №2, способ оплаты | Вставьте Webhook URL в кассу; адрес также передаётся как `notification_url` | [API `api.fk.life`](https://docs.freekassa.net/) |

Datagio использует серверные ключи `pk_live_...` и `sk_live_...`, эндпоинт `/merchant/v1/payment-links`. Магазин должен пройти модерацию. Укажите `webhook_secret` в магазине: Link-Bot принимает только подписанные уведомления `payment.succeeded` со статусом `paid`. Сумма проверяется по цене товара `amount`, а не по зачислению после комиссии `merchant_credit`.

Kassa AI использует отдельные реквизиты своей кассы и API `https://api.fk.life/v1/orders/create`: `44` — СБП, `36` — карты РФ, `43` — SberPay. Mini App передаёт IP покупателя; для оплаты непосредственно из Telegram-бота заполните поле «IP для платежей из бота». Email берётся из профиля/настроек или формируется как `TelegramID@telegram.org`. Задайте URL уведомлений в кассе; для переопределения `notification_url`, `success_url` и `failure_url` через API может потребоваться включение этой возможности поддержкой сервиса.

AntiloPay использует два разных ключа: приватный ключ мерчанта для исходящих запросов и публичный ключ проекта для Callback. Вставляйте Base64-значение, выданное кабинетом, без заголовков PEM. Приватный ключ должен быть RSA PKCS8, публичный — RSA SubjectPublicKeyInfo. Email покупателя берётся из подтверждённого Google-профиля или запрашивается в Mini App перед оплатой. IP передаётся из запроса Mini App.

Tribute подключается через **Shop API**, с разовыми заказами `period=onetime`. Нужен магазин, принимающий обычные платежи: магазин только для Stars не возвращает браузерную ссылку. Прежняя интеграция Tribute для подписок Telegram продолжает использовать свой отдельный тип платежа.

Описание заказа включает срок, устройства и трафик из тарифа/пакета. Успешное уведомление проходит проверку подписи, номера заказа, суммы и валюты. Для MulenPay, где подпись callback не описана, Link-Bot дополнительно запрашивает реальный статус платежа через авторизованный API. Повторный вебхук не начисляет покупку повторно.

## Названия, копии и методы оплаты

В **Админка → Тарифы → Способы оплаты** карандаш открывает отдельное окно с названием, описанием и методами платёжки. Пустые подписи используют системные значения. Кнопка с двумя листами рядом с карандашом создаёт копию: у неё свои подписи, методы и позиция, а ключи интеграции общие. Удаление копии доступно в её редакторе. После «Готово» сохраните изменения в тарифах; отмена редактирования тарифов восстанавливает весь список.

Можно выбрать один или несколько методов. Например, для строки «СБП» ЮKassa — СБП и SberPay, для строки «Карта» — только банковскую карту. Если API умеет открыть лишь один конкретный метод, покупатель выбирает его из разрешённых перед созданием счёта. При единственном методе дополнительного выбора нет. Это работает в кабинете и Telegram, включая оплату подарков, устройств и трафика в кабинете. Сервер проверяет разрешённый метод повторно; подмена запроса не расширяет список.

Поддержка зависит от API провайдера, а не от содержимого его веб-страницы. Редактор различает ограничение способов, предпочтительный выбор и отсутствие фильтра. Старые настройки без выбранных методов сохраняют прежнее поведение.

Копирование и подписи доступны для всех подключённых платёжных провайдеров. Баланс, Telegram Stars и ручной P2P не дублируются: у них нет внутренних методов провайдера. Paycore остаётся недоступным до реализации его API.

Список из кассы обновляется при открытии редактора и кнопкой обновления. При недоступности API показывается предупреждение и известные методы API; доступность конкретного метода проверяет платёжная система при создании счёта. Эти запросы выполняются только в редакторе, не замедляют `/start` и загрузку кабинета.

## Переход на платёжную страницу

Все платёжные страницы в Mini App открываются одинаково: **на ПК — в текущем окне Mini App**, **на телефоне и планшете — в браузере**. Это относится к тарифам, подаркам, устройствам и трафику. В веб-версии на ПК используется текущая вкладка. Telegram Stars открывает встроенный счёт Telegram; баланс и ручной P2P обрабатываются своими формами.

Для Crypto Pay в Mini App используется [веб-страница счёта `web_app_invoice_url`](https://help.send.tg/en/articles/10279948-crypto-pay-api), чтобы оплата не уводила пользователя в чат Crypto Bot.

## Сервисы, для которых нужна документация

В каталоге присутствует [Paycore](https://paycore.pw/), но включить его пока нельзя: интеграция отложена до получения документации. У других сервисов с таким названием API может отличаться.

Для продолжения нужны документация от поддержки сервиса или доступная ссылка на неё: создание счёта, авторизация, формат уведомления, подпись/проверка статуса и ответ на вебхук. До реализации такие сервисы не показываются покупателю среди способов оплаты.

## PayHot

В **Админке → Интеграции → PayHot** укажите рабочий API-ключ кассы (`phk_v2_…`), выданный PayHot **Webhook signing secret** и выберите способ оплаты. Ключу нужно право `merchant.payments.create`; выбранный способ и **RUB** должны быть подключены к кассе. Скопируйте показанный Webhook URL в раздел **Webhook** проекта PayHot и выберите `payment.succeeded`, затем включите и сохраните интеграцию.

Доступны СБП, карты, SberPay, криптовалюта, Apple Pay и Google Pay — в зависимости от настроек кассы. Email при необходимости покупатель вводит на странице оплаты. Тестовые ключи и события Sandbox не зачисляют реальные платежи.

Используется API v2, суммы в копейках и постоянный ключ идемпотентности для заказа. Подпись HMAC-SHA256 проверяется по исходному телу с допуском времени 5 минут. Оплата подтверждается только по `payment.succeeded` с полной списанной суммой, совпавшими заказом, ID платежа и валютой. Повторные уведомления не зачисляются повторно. При смене секрета обновите его в Link-Bot перед включением нового webhook endpoint.

Страница оплаты может находиться на домене, выбранном PayHot: Link-Bot использует готовый `checkout.url` целиком. Если API отклоняет создание счёта, покупатель получает понятное сообщение; администратор с доступом к интеграциям или диагностике дополнительно видит HTTP-статус, код PayHot и `request_id`. При `payment_amount_out_of_range` проверьте допустимую сумму выбранного способа оплаты в кассе, в том числе после применения промокода.

## Smerch

В **Админке → Интеграции → Smerch** укажите рабочий API-ключ `live_…` из **Smerch → Настройки → Интеграция и API**. Методы настраиваются в **Тарифы → Способы оплаты → Smerch → карандаш**; в интеграции нет второго выбора методов. Методы должны быть подключены к кассе, поддерживать RUB и возвращать `payment_url`. H2H-реквизиты без ссылки и рекуррентный `sbp_recurring` не поддерживаются.

Скопируйте показанный **Webhook URL** в настройки Smerch, включите webhook и сохраните интеграцию. Искать отдельный секрет в кабинете для подключения не требуется: перед выдачей покупки Link-Bot обязательно запрашивает транзакцию через защищённый API Smerch, сверяет её ID, заказ, сумму, RUB, метод и статус `paid`.

Если отдельный webhook secret у вас уже есть, укажите его в свёрнутом разделе **«Дополнительно: подпись вебхука»**. Тогда дополнительно проверяется HMAC исходного тела, а неверная или отсутствующая подпись отклоняется без перехода в режим без секрета. ID ключа необязателен; при его заполнении во время ротации выбирается только соответствующая подпись. В API Smerch выдача нового секрета описана отдельным `POST /api/v1/integration/webhook/rotate-secret`: обычное сохранение Link-Bot не меняет секрет и настройки других интеграций Smerch.

Для отдельных кнопок СБП и криптовалюты создайте копию Smerch в списке способов оплаты и назначьте каждой её метод. Один метод открывается сразу; дополнительный выбор появляется только если администратор сам назначил одной строке несколько методов в редакторе тарифов.

В **Тарифы → Способы оплаты → Smerch → карандаш** можно менять подписи, логотип и ограничивать методы отдельной кнопки. Копии используют общие ключи, но свои подписи и методы. Старый `paymentMethod` используется только как запасной метод для ненастроенной строки (по умолчанию СБП). Сохранённый предыдущей версией список `paymentMethods` в интеграции не ограничивает методы, назначенные копиям в тарифах.

API: `https://api.smerch.io/api/v1/integration/transactions`. Запросы подписываются HMAC v2 тем же API-ключом, суммы передаются целыми копейками, `external_id` — номер покупки Link-Bot. Передаются стабильный `metadata.userId` из ID клиента и публичный IP веб-покупателя. Комиссия покупателя не подменяет сумму заказа: сверяется `amount`, а не `gross_amount` или `net_amount`. Повторные уведомления не начисляют покупку повторно; возвраты, неполные и тестовые платежи не выдают подписку. Временные ошибки подтверждения или исполнения возвращают 5xx для повторной доставки.

Комиссии, холд, условия и сроки вывода задаются договорённостями с Smerch; Link-Bot их не меняет и не добавляет фиксированную комиссию к тарифу.

Логотип: [официальная иконка приложения](https://smerch.io/apple-icon.png), файл `payment-smerch.png`. Протокол: [официальная документация](https://docs.smerch.io/llms.txt).


## Лавешка · Lave Pay

1. Получите API-ключ в приложении Лавешки → Lave Pay и добавьте его в **Интеграции → Лавешка**.
2. Укажите отдельный секрет подписи вебхука и курс **₽/USD** (например, `100` означает 100 ₽ за доллар). В настройках вебхуков Lave Pay сохраните тот же секрет и скопированный Webhook URL. Отправьте тестовое событие: Link-Bot проверит подпись и ответит `OK`, без начислений.
3. Включите Лавешку у нужных тарифов. Отдельных переключателей СБП / криптовалюты в интеграции нет: выбор происходит на платёжной странице провайдера. Подписи и логотип можно изменить в существующем редакторе способов оплаты.

Link-Bot создаёт hosted-счёт через `POST https://laveshka.io/merchant/v1/invoices`, авторизация `X-Api-Key`, сумма в USD строкой и уникальный `order_id` по номеру покупки. Например, 300 ₽ при курсе 100 ₽/USD превращаются в 3,00 USD; дробные центы округляются вверх. Принимаются счета от 0,10 до 10 000 USD. При выходе за лимиты предлагается выбрать другой способ, сумма не подменяется минимальной. Счёт действует один час. Сервис может добавлять свои комиссии.

В базе сохраняются исходные копейки RUB и центы USD, ID счёта и магазина. Перезапуск и изменение курса не пересчитывают ожидающую оплату. Проверяется HMAC-SHA256 `timestamp.raw_body` с секретом вебхука, срок подписи и принадлежность магазину. Перед выдачей покупки бот дополнительно запрашивает счёт через API и сверяет `id`, `merchant_id`, `order_id`, `currency`, `face_amount` и статус `paid` с сохранёнными суммами. Используется номинал счёта, не сумма после комиссии. Повторная доставка не начисляет покупку повторно. Недоплаты, возвраты и тестовые события не активируют подписку; временные ошибки API или базы возвращают 5xx для повторной доставки.

Платёжная ссылка `https://t.me/laveshka?startapp=...` открывается через Telegram, если кабинет запущен в Mini App. В браузере открывается обычная Telegram-ссылка. Поддерживаются существующие покупки подписок, подарков, устройств и трафика; автоматическое списание не подключается.

Протокол и логотип: [официальная документация](https://laveshka.io/docs/lave-pay), [иконка](https://laveshka.io/icon.svg).
